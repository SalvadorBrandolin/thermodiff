Fortran code generation¶

Fortran code generation for thermodynamic models.

This module turns a DiffPlz instance into a free-form Fortran subroutine that evaluates the original function together with all its available derivatives.

The generated subroutine takes the independent variables (mole numbers n, volume V, pressure P, temperature T), the model parameters, and returns the function value and the derivatives as intent (out) arguments, for example:

subroutine f(n, V, T, f, dfdT, dfdV, dfdn)
  implicit none
  integer, intent(in) :: nc
  real(8), intent(in) :: n(:)
  real(8), intent(in) :: V, T
  real(8), intent(out) :: f, dfdT, dfdV
  real(8), intent(out) :: dfdn(:)
  ...
end subroutine

Summations produced with sum_components() are expanded into explicit do loops and the Kronecker deltas handled by DiffPlz become if/else blocks. Internal functions created with idx_function() (and their derivatives) are exposed as extra input arguments by default; pass strict=True to raise an error instead.

Generate a Fortran subroutine for a DiffPlz instance.

The behaviour options can be given as a CodegenOptions (options), as the legacy keywords documented below, or both. The resolved options are validated on every call: options that the generator would silently ignore for the chosen combination are disabled and reported in one UserWarning (see CodegenOptions.validate()). For ready-made option sets use CodegenOptions.from_preset("standard").

Parameters:

  • diff (DiffPlz) – The differentiated thermodynamic expression.

  • derivatives (str or list of str, optional) – Derivatives to emit, for example ["dT", "dV", "dn"]. Both the friendly names and the derivative attributes (["dt", "dv", "dni"]) are accepted, as well as the groups all, none, first and second (see thermodiff.derivatives.resolve_derivatives()). By default every non-zero derivative computed by diff is emitted.

  • name (str, optional) – Base name used for the generated variables. Defaults to the name attribute of diff.

  • subroutine_name (str, optional) – Name of the generated subroutine. Defaults to the base name.

  • strict (bool, optional) – When True, raise a ValueError if the expression contains internal functions or unresolved derivatives instead of exposing them as input arguments. By default False.

  • integer_args (list of str, optional) – Names of extra arguments that must be declared as integer, intent(in) (for example, extra dimensions).

  • module_symbols (list of str, optional) – Names that are provided by a use statement of the enclosing module. They are neither declared as arguments nor included in the subroutine signature.

  • optional_derivatives (bool, optional) – When True, every output - the function value included - is declared as a Fortran optional argument and computed only when the caller passes it. A shared temporary is skipped whenever none of the outputs that need it is present, so calling the subroutine with a subset of the outputs also skips the work.

  • array_cse (bool, optional) – When True (the default), index-dependent sub-expressions that several outputs share are materialised into array temporaries computed a single time (see _indexed_cse()). Only sub-expressions of rank up to two are materialised, because a larger temporary costs more than it saves. Disable the pass to obtain the plain, fully inlined expressions.

  • share (bool, optional) – When True (the default), summations and common scalar sub-expressions shared by several outputs are computed a single time as internal temporaries (_share_sums() and _common_scalar_cse()). Set it to False to disable both sharing passes: every output is then emitted from its own fully inlined expressions and repeated summations are re-evaluated per output. The benchmark variant “V1 none” is array_cse=False, share=False; “V2 partial” is array_cse=False; “V3 full” is array_cse=True. The flag only changes the generated body: the signature, the declaration block and the output order are identical for every setting.

  • stats (dict, optional) – When given, it is filled in place with generation statistics: operation_count (sympy.count_ops summed over the final output expressions and over the body of every shared temporary), operation_count_tool (the exact tool/options used) and n_temporaries (number of shared temporaries emitted). The count is a symbolic-operation count of the final expressions, not a runtime estimate.

  • share_sums (bool, optional) – Fine-grained control of the two passes enabled by share: _share_sums() and the scalar common sub-expression pass. None (the default) inherits the value of share. Used by the ablation study.

  • scalar_cse (bool, optional) – Fine-grained control of the two passes enabled by share: _share_sums() and the scalar common sub-expression pass. None (the default) inherits the value of share. Used by the ablation study.

  • options (CodegenOptions, optional) – Behaviour options. Defaults to CodegenOptions(), that is the defaults of the behaviour keywords. A keyword passed explicitly in the same call overrides the matching field of options.

  • **legacy – Any behaviour option by name (strict, optional_derivatives, chain_rule, …; see the entries of this section and the fields of CodegenOptions). An unknown name raises TypeError.

  • symmetric_params (iterable of str, optional) – Names of rank-2 parameters known to be symmetric (declared with the symmetric attribute in a .model file).

  • param_symmetry (bool, optional) – Exploit symmetric_params: canonicalise their subscripts and fold symmetric double summations into a triangular loop (see _fold_symmetric_sums()). Off by default.

  • hessian_symmetry (bool, optional) – Compute only the upper triangle of the composition Hessian dfdndn (j >= i) and mirror it. Exact by Schwarz’ theorem. Off by default.

  • cse_backend ({"thermodiff", "sympy"}, optional) – Algorithm of the scalar common sub-expression pass.

  • sum_alpha (bool, optional) – Share summations that are equal up to the names of their bound indices (alpha equivalence), not only syntactically identical ones. Off by default.

  • array_pad (int, optional) – Extra rows added to the leading dimension of rank-2 array temporaries (t(nc + pad, nc)). Zero (the default) keeps t(nc, nc).

  • hoist_invariants (bool, optional) – Move costly sub-expressions that do not depend on every bound index of their summation out of the loop, into temporaries of lower rank (see _hoist_invariants()). Off by default.

  • chain_rule (bool, optional) – Differentiate by the chain rule over the summation nodes of the function, as a hand-written implementation does (see thermodiff.chain). Falls back to the plain derivatives when the function does not fit the pattern. Off by default.

  • hoist_loops (bool, optional) – Group the terms of every loop body over free indices by their index-dependent factors and compute the loop invariants once (see _hoist_loop_invariants()). Off by default.

  • sum_free_alpha (bool, optional) – Share summations equal up to the names of their bound and free indices (sum_k x(i,k) and sum_l x(j,l)). Off by default.

  • fuse_temps (bool, optional) – Do not materialise cheap rank-2 array temporaries that are only read inside summations: their body is inserted into the summation (see _fuse_temporaries()). Off by default.

  • nest_sums (bool, optional) – Rewrite double sums as dot products with vector sums that other outputs already need (see _nest_double_sums()). Off by default.

  • split_sqrt (bool, optional) – With chain_rule: split sqrt(c*A_a*A_b) into sqrt(c)*sqrt(A_a)*sqrt(A_b) for per-component temperature functions. Assumes they are non-negative (true for the attractive parameters of cubic equations). Off by default.

  • split_sums (bool, optional) – With chain_rule: expand summation bodies and split sums of terms into sums, so that each term can become a dot product with a vector sum. Off by default.

  • nest_shared (bool, optional) – With nest_sums: also nest double sums whose inner sum is shared by several double sums (not only by an output), and count equal summations once when deciding whether to fuse a temporary. Off by default.

  • sym_matvec (bool, optional) – With param_symmetry: emit the vector sums v(f) = sum_b P(b,f) R(b) with a symmetric P as a symmetric matrix-vector product that reads only the upper triangle. Off by default.

  • col_major (bool, optional) – Order the loops of vector sums and rank-2 tables so that the arrays they read are traversed along columns (see _prefers_column_order()). Off by default.

  • pair_cse (bool, optional) – With chain_rule: write pair functions in terms of earlier ones (tau*exp(-c tau) as tau*M), and write the temperature derivatives of pair functions with a cheap pair-dependent logarithmic rate in place (M' = M*r_ab). Off by default.

  • pair_rates (bool, optional) – With chain_rule: write pair functions in terms of earlier ones (tau*exp(-c tau) as tau*M), and write the temperature derivatives of pair functions with a cheap pair-dependent logarithmic rate in place (M' = M*r_ab). Off by default.

  • chain_factor_sums (bool, optional) – With chain_rule and fuse_temps: move the factors that depend only on the free indices out of the reductions of the structured derivatives (sum_k qs(i)*qs(j)*w(k)*tau(i,k)*tau(j,k) becomes qs(i)*qs(j)*sum_k w(k)*tau(i,k)*tau(j,k)), as the plain path does. Fewer multiplications in the inner loops; last-bit rounding differences. Off by default here; on in the "standard" and "fastest" presets.

  • sum_transpose (bool, optional) – With sum_free_alpha: reuse a rank-2 summation that is the transpose of another one. Off by default.

  • sep_sums (bool, optional) – Distribute products over sums in summation bodies, split the sums and move out the factors that do not depend on the bound index (see _separate_sums()). Off by default.

  • sym_rank3 (bool, optional) – With param_symmetry: also canonicalise symmetric parameters of rank three or more (fully symmetric tensors). Off by default.

  • nest_general (bool, optional) – With nest_sums: also nest sums over three or more indices, and use rank-2 summations as inner sums. Off by default.

  • sym_sum2 (bool, optional) – With param_symmetry: a rank-2 summation whose body is symmetric in its two free indices is computed on the upper triangle and mirrored. Off by default.

  • cse_expensive (bool, optional) – The indexed CSE extracts a costly single-operation sub-expression (log, exp, a root) already when it is used twice. Off by default.

  • fuse_loops (bool, optional) – Merge consecutive vector sums with the same loop structure into one loop nest (see _fuse_loop_nests()); only without optional outputs. Off by default.

  • nested_nodes (bool, optional) – With chain_rule: index-free summations nested inside a node become nodes too, and derivatives are composed through them (see thermodiff.chain._nest_inner_nodes()). Off by default.

  • sym_perm (bool, optional) – Rewrite the subscripts of symmetric parameters inside loop nests so that the innermost loop index comes first (contiguous access). Exact by symmetry; applied after every other pass. Off by default.

  • fuse_guard (bool, optional) – With fuse_temps: never inline an expensive rank-2 temporary (transcendental body) that two or more different summations read, nested ones included. Off by default.

  • nest_cost (bool, optional) – With nest_sums and nest_general: nest every sum over three or more indices into an inner rank-2 table, even when no other output shares it. Off by default.

  • comp_fuse (bool, optional) – Fuse consecutive per-component maps (cmp0, cmp0_T, …) into one loop with a per-element common sub-expression elimination. Only without optional_derivatives. Off by default.

  • dummy_canon (bool, optional) – Merge the terms of a summation over two or three indices that are images of each other under a renaming of the bound indices (e.g. (b_k + b_l + b_m) with a symmetric tensor). Exact. Off by default.

  • float_canon (bool, optional) – Round every floating-point constant to its double value with a single representation before the common sub-expression passes. Off by default.

  • contiguous_args (bool, optional) – Declare every assumed-shape array argument (parameters, mole numbers and outputs) contiguous, so the compiler can drop the stride arithmetic and the multi-versioned loops. A caller that passes a non-contiguous section gets a copy-in/copy-out (still correct). Off by default.

  • fuse_outer (bool, optional) – Fuse consecutive per-component maps and scalar reductions that share the outer loop 1..nc into one loop. Only without optional_derivatives. Off by default.

  • fuse_libm_guard (bool, optional) – With fuse_outer, never fuse a double reduction into the outer loop of a map that calls exp, log, sqrt or a real power, so the map stays vectorisable. Off by default.

  • keep_libm_tables (bool, optional) – With fuse_temps, never inline a rank-2 temporary that calls a libm routine into a summation; it stays a table computed by its own map loop. Off by default.

  • table_layout (bool, optional) – With chain_rule, store a non-symmetric pair function in the subscript order of the parameters it reads (G(l, k) for exp(-c_lk tau_lk)) instead of the alphabetical order of the summation indices, so the table is written contiguously and the sums that read it take the contiguous inner index; with col_major a rank-2 sum that then reads its tables with the bound index last (sum_k G(i, k) H(j, k)) is emitted in jki order. Off by default.

  • lowrank_hess (bool or "sym", optional) – Assemble a rank-2 output (the composition Hessian) whose residual has separable terms c F(i) G(j) in rank-k form: the terms are grouped by the factor over one index, sum_l r_l(i) G_l(j), with the coefficient vectors r_l computed once (O(nc)); terms over one index and pair terms are kept. Applied only when it lowers the per-element operation count. True emits the full square in column order without mirror; "sym" keeps the triangle and mirror of hessian_symmetry. Only without optional_derivatives. Off by default.

  • drop_pair_tables (bool, optional) – Do not materialise a rank-2 table read only by scalar reductions (one double, triangular reduction and its diagonal sums) whose body calls no libm routine: its body is inlined there. In the scalar double reductions the factors over the outer index are applied once per outer iteration and the products over the inner index only become vectors. With fuse_libm_guard a single reduction that calls a libm routine does not share the outer loop of a double reduction either. Only without optional_derivatives. Off by default.

  • share_elementwise (bool, optional) – A costly rank-1 sub-expression (log, exp, a root of a per-component expression) read in two or more places – the body of a scalar reduction over k and an output over i – is computed once as a vector that every place reads. Occurrences are compared up to the index name and to the spelling of their scalar prefactors (x/y and (1/y)*x); differently spelt scalar temporaries of the shared occurrences are merged. Only without optional_derivatives. Off by default.

  • scalar_chain (bool, optional) – With chain_rule, compute the partial derivatives of the outer function F(S_1, ..., S_m, V, T) by forward second-order propagation over its expression DAG, followed by one common sub-expression elimination, instead of differentiating the expanded F (see thermodiff.chain._scalar_chain()). They become scalar temporaries computed after the reductions they read, and the outputs read them. Falls back to the plain path when F is not smooth (Piecewise, Max …). "cost" generates the kernel both ways and keeps the one with the lower operation_count (stats["scalar_chain_used"] tells which). With "estimate" the choice is made before the array pipeline, from the operation counts of the plain partials of F (after one CSE) and of the propagated definitions, so the pipeline runs once. Only without optional_derivatives. Off by default.

  • split_affine (bool, optional) – In a summation with free indices, sum_m (c - P(m, k, l)) w(m) with c and w independent of the free indices becomes c*S - sum_m P w: the scalar S = sum_m w(m) is computed once and the readers of the table read S - t, so the innermost body is one multiply-add; products of factors over the bound index only become vectors (see _split_affine()). Applied only when the body gets cheaper; only without optional_derivatives. Off by default.

  • split_acc (int or bool, optional) – 2: in the inner loop of a symmetric rank-2 table filled by a sum that reads a parameter of rank three (the O(N^3) nest of CMR), use two scalar partial accumulators per sum (even and odd m, one remainder iteration, then their sum), so that gcc vectorises the reduction without -ffast-math (reportes/brechas/ronda3-cmr-o3.md). Changes the summation order. Only without optional_derivatives. Off by default.

  • sparse_parameters (iterable of str, optional) – Names of array parameters that are mostly zero (the group-count matrix of UNIFAC). Work that is multiplied by an element of one of them is skipped where the element is zero: a reduction term v(l, k)*f is accumulated under if (v(l, k) /= 0), and a table whose every read is multiplied by the same element (the log(sum_m th psi) table and its temperature derivatives) is not evaluated there, so its entry is never read. Applied only to plain loop nests, and only when the skipped work calls a libm routine or is a nested loop, so that dense parameters do not get slower. Names that are not array parameters of the model are dropped with a UserWarning. The results agree with the unguarded kernel up to the reassociation of the accumulations. A table whose body is a multiple of the element is set to zero where the element is zero, even if the unguarded expression would give NaN or Inf there (log(0)*0). Empty (no guards) by default.

  • canonical_placeholders (bool, optional) – Name the derivatives of placeholder functions by their differentiation variables instead of their index labels: the gradient of B(n) is one argument dBdn(:) read as dBdn(i) and dBdn(j) (instead of two arguments dBdi and dBdj with the same data), its Hessian is dBdndn(:, :) (declared symmetric, so dBdndn(j, i) is read as dBdndn(i, j) under param_symmetry) and mixed derivatives put the scalar variables first (dDdTdn for both orders of T and n_i). The common sub-expression and symmetry passes then see that the copies are equal. False restores the index-label names (dBdi, dBdj, dBdidj). On by default (and in every preset); the legacy keyword defaults of to_fortran keep it on too.

  • work_array (bool, optional) – Store every array temporary in one automatic array work_ instead of one automatic array each: the subroutine calls an internal procedure <name>_body (the usual kernel) with one element of work_ per temporary, which it receives as an explicit-shape array. Without -fstack-arrays gfortran allocates automatic arrays on the heap, so this turns one malloc/free pair per temporary into one per call. Same arithmetic. Ignored with max_nc. Off by default.

  • max_nc (int, optional) – Give every array temporary the compile-time extent max_nc (t(max_nc, max_nc), used up to nc), so it lives on the stack without -fstack-arrays. The kernel starts with if (nc > max_nc) error stop; callers with larger nc must dispatch to another kernel. A temporary above gfortran’s -fmax-stack-var-size default (65536 bytes: max_nc <= 90 for rank 2, <= 20 for rank 3) is made static by gfortran (not thread safe), so a UserWarning is emitted. Same arithmetic. None (the default) keeps nc-sized temporaries.

  • real_kind (str, optional) – Kind of every real: "8" (the default) emits real(8) and d literals, as always. Any other integer ("16") or the name of a kind constant ("pr") emits real(<kind>) for the dummies, temporaries, work arrays and results, and literals as 1.0_<kind> (1.5e-10_<kind>). The arithmetic is the same. The digits of a literal are those that SymPy prints (about 17 significant ones for floats and pi): with a quad kind these constants keep double-precision accuracy. Write exact values (integers, rationals) or pass them as inputs when that matters. The kind constant must not be the name of a model symbol.

  • kind_module (str, optional) – Module that exports the kind constant real_kind: the subroutine gets use <kind_module>, only: <real_kind> (so real_kind="pr", kind_module="yaeos__constants"). Ignored for an integer real_kind.

Returns:

The free-form Fortran source code.

Return type:

str

  • ValueError – For an invalid option value (see CodegenOptions.validate()).

Code generator options¶

Typed, immutable options of the Fortran generator.

CodegenOptions groups the behaviour options of thermodiff.fortran.to_fortran(). Per-call context (the differentiated object, the selected derivatives, names, extra arguments and so on) is not part of it. The legacy keyword values (False/True/strings) are mapped to enums by CodegenOptions.from_legacy() and back by CodegenOptions.to_legacy().

Extra scalar variables: the scalar core recipe¶

Besides T, V, P and n[i], a DiffPlz can differentiate with respect to extra scalar symbols given in variables. This supports models written as a small scalar core F(B, D, D1, nT, V, T) (a cubic equation of state in the mixture level covolume B, attraction D …) whose arguments depend on the composition through mixing rules. The generator differentiates the core with respect to its scalars and the chain rule over the composition is assembled by a generated routine, which gives the hand-factored cost structure.

import sympy as sp
import thermodiff as td

B, D, D1, nT = sp.symbols("B D D1 nT")
core = -nT * sp.log(1 - B / td.V) - D / (D1 * td.T) * sp.log(...)
diff = td.DiffPlz(core, name="f", variables=[B, D, D1, nT])
code = td.to_fortran(diff)  # every non-zero derivative, or select:
code = td.to_fortran(diff, derivatives=["dB", "dBdD", "dBdT", "dV"])

Names are those of the thermodynamic derivatives with the variable name: dB, dB2, dBdD, mixed with the thermodynamic variables dBdT, dBdV, dBdP, and dndB (an array over n[i] when the expression depends on n). Within a mixed derivative the order is n, the declared variables in declaration order, then T, V, P (other orders are accepted). The outputs are dfdB, dfdBdD, dfdndB … and the variables are real(8), intent(in) scalar arguments. Variable names are case sensitive and cannot be T, V, P or n. The groups first, second and all include them (and, as always, emit zero outputs for the variables the expression lacks). With derivatives=None every derivative, the scalar ones included, is computed and the non-zero ones are emitted; without variables nothing changes. The derivatives are also stored in DiffPlz.scalar_derivatives (keys such as "var_dBdD").

With mixing rules x_r(n) for the scalars x_r (B = b.n, D = n.a.n, nT = sum(n) …), the composition derivatives follow from the chain rule:

\[\frac{\partial F}{\partial n_i} = \sum_r F_{x_r}\,\frac{\partial x_r}{\partial n_i}, \qquad \frac{\partial^2 F}{\partial n_i \partial n_j} = \sum_{r,s} F_{x_r x_s}\,x_{r,i}\,x_{s,j} + \sum_r F_{x_r}\,x_{r,ij}\]

and likewise F_{T n_i} = sum_r F_{T x_r} x_{r,i} (dBdT … with T and V). Scalars may also depend on T and V (D(n, T)): the routine below includes those terms.

The assembly routine¶

thermodiff.scalar_chain_routine() emits that step as a Fortran routine, so no hand-written assembly is left. Declare the scalars in the order of variables, which of T and V each one depends on (all depend on n) and which are linear in n (no Hessian input):

names = ["B", "D", "D1", "nT"]
kwargs = dict(
    linear=["B", "D1", "nT"],       # d2x/dn dn = 0 for these
    derivatives=["dT", "dV", "dn", "dndT", "dndV", "dndn"],
)
# D = n.a.n * alpha(T) would be depends_on={"D": ["T"]}
wanted = td.scalar_chain_core_derivatives(names, {}, **kwargs)
core_code = td.to_fortran(diff, derivatives=wanted)
chain_code = td.scalar_chain_routine(names, {}, **kwargs)

scalar_chain_core_derivatives lists the derivatives to request from the core (dB, dBdD, dBdT, dT …), and the routine reads exactly those as inputs named as the core kernel emits them (dfdB, dfdBdD, dfdT2 …; core_name changes the prefix). Per scalar X the inputs are its gradient dXdn(nc) and Hessian dXdndn(nc, nc), and if it depends on T: dXdT, dXdT2, dXdndT(nc) (dXdTdV when it depends on both). The outputs are the total derivatives with the usual names and prefix dar (name): dardT, dardV, dardT2, dardTdV, dardV2, dardn, dardndT, dardndV, dardndn, selected by derivatives like in to_fortran. With CodegenOptions(optional_derivatives=True) every output and input is optional and an output is computed when present (give its inputs); real_kind and kind_module are honoured. The Hessian loop works on the lower triangle and mirrors it, with O(m) work per element for m scalars. tests/test_scalar_variables.py compares the core kernel plus this routine with the kernel written directly in the mole numbers.

Placeholders with expression arguments¶

A placeholder whose argument is an expression, for example alpha(k, delta(n, V), tau(n, T)) in a multifluid model, is treated as a function of the variables the expression contains, and the generated kernel asks the caller for its total derivatives with respect to them (dalphadn, dalphadV …). The generator does not apply the chain rule through the arguments, and emits a UserWarning naming the placeholder and the expression. To get the chain rule through delta and tau, make them scalar variables of the placeholder’s core and use the recipe above: generate the mixture layer with variables=[delta, tau] written as symbols, supply alpha and its partial derivatives with respect to them, and assemble.

Compiler flags and storage of temporaries¶

Generated kernels keep their intermediate arrays (t3(nc, nc) …) as automatic arrays. gfortran puts automatic arrays on the heap unless the kernel is compiled with -fstack-arrays (implied by -Ofast), so without the flag every call pays one malloc/free per temporary. Compile generated kernels with -fstack-arrays: on the PC-SAFT, CMR, PR76, NRTL, UNIQUAC and UNIFAC kernels of the fastest preset (-O3 -funroll-loops, nc = 2 to 50) it was 10% faster than the heap at the median and up to 2x at small nc; the gain vanishes around nc = 50. The stack it needs is small (at most about 420 KB at nc = 100 in those models, against the usual 8 MB limit). For larger systems or OpenMP threads raise the limit (ulimit -s, OMP_STACKSIZE). Intel ifx and ifort use the stack for automatic arrays by default.

Two opt-in options change the storage instead; neither is enabled by a preset, because neither is faster everywhere:

work_array=True

One automatic work_ array holds every temporary, and the kernel calls an internal procedure that sees them as explicit-shape arrays. Useful when the build cannot use -fstack-arrays: without the flag it took 0.4x to 1.0x the time of the default at small nc (median 0.8x at nc = 2), but up to 1.16x on some PR kernels at nc = 50. With the flag it adds nothing in most kernels, is slower in some (up to 2.5x on a PR kernel at nc = 2), and is 25 to 35% faster on the full UNIFAC output set. Measure before adopting it.

max_nc=N

Every temporary gets the compile-time extent N along nc and the kernel stops (error stop) when nc > N. Pick N close to the largest nc you use: with N of 10 to 100 kernels were typically 3 to 9% faster than with work_array, and slower on some (up to about 1.4x; UNIFAC full 1.6x). Larger values buy nothing and cost memory: an array above 64 KB (a rank-2 temporary with N above about 90) becomes static, so the kernel is no longer thread safe (the generator warns); N = 1000 needs 8 to 40 MB per kernel, and N = 10000 gigabytes (some kernels no longer link). Extents along other dimensions (ng) stay automatic, so for UNIFAC-like models a large N makes every call allocate N x ng arrays: 100x slower at N = 10000. max_nc disables work_array.

Sparse parameters¶

CodegenOptions(sparse_parameters=("v",)) (or v nc ng sparse in a .model) names array parameters that are mostly zero, such as the group-count matrix of UNIFAC. Work that is multiplied by an element of one of them is skipped where the element is zero: the terms of a reduction run under if (v(l, k) /= 0.0d0), and a table that is only read through such terms (the log of a sum over groups and its temperature derivatives) is not evaluated there. A table that is itself a multiple of the element is set to zero where the element is zero, even if the unguarded expression would be NaN or Inf (log(0)*0). Guards are emitted only where the skipped work is a transcendental call or a nested loop. The option is off by default and the generated code without it does not change. Because it tests values at run time, a dense parameter makes the kernel slower (about 10% on UNIFAC), so enable it only for sparse data.

Workload mode: fixed-output kernels and a dispatcher¶

optional_derivatives=True gives one kernel for any output set, but it pays a fixed cost on every call and disables the loop passes of the fastest preset. The workload mode keeps that single public procedure and makes it cheap. From the command line:

thermodiff-model nrtl.model --preset fastest \
    --workload dn,dndn --workload dT --derivatives dT,dn,dndn

or from Python, compile_model(text, workloads=["dn,dndn", "dT"]) and thermodiff.workload_module() for a DiffPlz object. The module contains

  • a dispatcher <model>_derivs with the signature of the optional kernel; it builds a bit mask from present() and selects, with select case, the kernel whose output set is exactly the present set;

  • one fixed-output kernel <model>_derivs_w<k> per workload, generated with optional_derivatives=False and the chosen preset (explicit-shape dummies, !GCC$ ATTRIBUTES NOINLINE);

  • the optional kernel <model>_derivs_fallback, used for every other combination of present outputs. --derivatives selects its outputs and must cover the workloads.

A workload is matched by the output set of its kernel, including the function value when the kernel computes it. A call with a larger set is not served by a covering kernel (that would need scratch arrays for the extra outputs); it goes to the fallback.

--fixed-nc 2,3 (fixed_nc=(2, 3)) also emits, for each workload and each size, a copy <model>_derivs_w<k>_nc<size> where nc is a named constant (the dummy nc_in keeps the signature). The compiler then unrolls the loops, drops the array descriptors and keeps the temporaries on the stack. The dispatcher selects by nc and then by output set.

Pitfalls handled by the generator (measured with gfortran 16): the dispatcher’s optional array dummies are not contiguous (an absent actual argument could be packed, and crash), while its inputs are; the kernels have explicit-shape dummies so that forwarding makes no copy; and the kernels are not inlined into the dispatcher, which would make them lose the contiguity facts. Dimensions other than nc (for example ng) are forwarded from the kernels’ own dummy lists; their arrays keep assumed shape in the kernels unless the extents are known (the .model front end passes them). Explicit shape re-strides an actual array whose leading extents differ from the declared ones (a (3, 3) array passed with nc = 2), so the dispatcher calls a fixed-output kernel only when every array of rank two or more, input or output, has exactly the declared extents in all dimensions but the last; otherwise it calls the fallback, which is always correct.

Fused workloads of a scalar core¶

A scalar core (DiffPlz(..., variables=[...])) normally takes two calls: the core kernel and the chain-rule routine (thermodiff.scalar_chain_routine()). thermodiff.scalar_chain_workload_module() emits instead one subroutine per workload, given as a selection of chain outputs:

td.scalar_chain_workload_module(
    core, ["B", "D", "E", "S"], [["dv", "dni"], ["dt", "dv", "dni"]],
    {"D": ["T"]}, total_moles=("S",), preset="fastest",
    module_symbols=["R"], uses=["consts, only: R"],
    subroutine_name="ar_fused",
)

Each kernel computes exactly the core derivatives its outputs need (as local scalars, with the code to_fortran generates for that set) and then the chain assembly, with no optional arguments and no present() tests. The dispatcher ar_fused(nc, <core inputs>, f, <scalar derivatives>, <outputs>) has optional f, scalar derivatives and outputs, and selects the kernel by the present() mask of the outputs and f; f (the function value) belongs to every kernel’s output set. Any other combination goes to ar_fused_fallback: all the core derivatives of the union, then the chain with optional outputs. That fallback needs the inputs of the chain routine (see its documentation: the total partials are computed when any second-order T/V output is present), and a workload kernel needs only its own. preset/options, real_kind, kind_module and module_symbols behave as in thermodiff.workload_module(); fixed_nc is not supported.

Caller contracts:

  • f must be present to reach a fast kernel. Every workload kernel computes the function value, so f is a bit of its output set; a call without f does not match any workload and goes to the (slower) fallback. Lifting this would need a kernel variant without f or a scratch output, which costs more than it saves, so it is a documented rule instead.

  • Every input of the selected workload (the scalar derivatives it reads) must be present. The mask counts outputs only, so a missing input is not detected: the dispatcher would pass an absent optional actual argument to a non-optional dummy, which is undefined behaviour. A mask that also counted the inputs would not help: the fallback reads the same inputs, so a call that lacks one is wrong on every path.

The dispatcher costs a few nanoseconds (the mask and forwarding); a caller that knows the output set can call ar_fused_w<k> directly. Measured (cubic core, nc 2 to 50): the fused kernel is within 4 percent of the direct core and chain calls for the [dv, dni] set and about 10 percent faster for a Jacobian set, and 0.8 to 1.0 times a dispatched core followed by an optional chain.

Fused workload kernels of a scalar core.

A scalar core is evaluated in two steps: the core kernel (to_fortran(core, derivatives=...)) gives the derivatives of F(x_1, ..., x_m; V, T) and the chain routine (scalar_chain_routine()) assembles the total derivatives from them. Called as two procedures every evaluation pays two calls, the copies of the intermediate derivatives and the optional argument tests of the chain routine.

scalar_chain_workload_module() emits instead, for each workload (a set of chain outputs such as ["dv", "dni"]), one subroutine that

  • computes exactly the core derivatives the workload needs, as local scalars, with the code the generator produces for that fixed set;

  • assembles exactly the outputs of the workload from them, with no optional argument and no present() test;

and a dispatcher with the full signature (optional outputs) that selects the subroutine by the present() mask of the outputs, as the workload mode does (thermodiff.codegen.workload, whose dispatcher it reuses).

The kernels are composed, not printed again: the core kernel is generated by to_fortran, parsed, and its derivative outputs become locals; the declarations and statements of the chain routine (chain_fragments()) are inserted after implicit none and before end subroutine.

Fallback¶

The kernel for any output set that is not a workload computes every core derivative that the union of the outputs needs and then runs the chain routine with optional outputs. That is the simplest correct choice: a core derivative is a function of the scalars alone, so computing one nobody asked for needs no extra input, and the fused all-optional kernel would otherwise need a present() test per core derivative. The value F is an optional output of the dispatcher too (bit of the mask), and so are the inputs that only some outputs need (scalar derivatives). The chain routine with optional outputs computes the total partials q_W,r when any second-order T/V output is present, so a call that is not a workload must pass the inputs of every such output it needs for all of T and V on which a scalar depends (the workloads have no such restriction).

Workload mode: fixed-output kernels behind one dispatcher.

optional_derivatives=True gives one kernel for any output set, but it pays a fixed cost on every call and disables the loop passes of the fastest preset. The workload mode keeps that single public entry point and makes it cheap:

  • one fixed-output kernel per requested output set (optional_derivatives=False, specialised by the generator);

  • the optional_derivatives=True kernel as a fallback;

  • a dispatcher with the public signature of the optional kernel. It builds a bit mask from present() and selects the kernel whose output set is exactly the present set with select case; any other combination goes to the fallback. Covering a request with a larger kernel would need scratch arrays for the extra outputs, which costs more than it saves.

Optionally (fixed_nc) every fixed-output kernel is also copied once per listed number of components, with nc turned into a named constant so that the compiler unrolls the loops, drops the array descriptors and keeps the temporaries on the stack. The dispatcher selects the copy by nc.

The module is built on top of to_fortran(): the kernels are generated one by one, parsed for their dummy arguments and rewritten textually (names, array dummies, directives). The dummy lists are read from the generated code, so extra integer dimensions and the placeholder arguments are forwarded without special cases.

Performance pitfalls handled here (measured by the yaeos benchmarks):

  • the dispatcher’s optional array dummies are not contiguous: an absent or disassociated actual argument would make gfortran try to pack it and crash; the inputs keep contiguous (they are never absent);

  • the fixed-output kernels get explicit-shape dummies (n(nc), dBij(nc, nc)), so forwarding the dispatcher’s arrays makes no copy and the descriptor handling disappears (about 7 % of a small kernel). Explicit shape re-strides an actual array whose leading extents differ from the declared ones, so the dispatcher calls such a kernel only when size(x, d) equals the declared extent of every dimension but the last of every array of rank two or more (inputs and outputs); otherwise it calls the assumed-shape fallback (shape_guard());

  • !GCC$ ATTRIBUTES NOINLINE on the fixed-output kernels: at -O3 gfortran inlines them into the dispatcher and the code loses the contiguity facts (up to 18x slower).

Generate a Fortran module with a workload dispatcher.

Parameters:

  • diff (DiffPlz) – The differentiated expression.

  • workloads (sequence) – Derivative selections, one fixed-output kernel each.

  • module_name (str, optional) – Name of the module; default <subroutine name>_mod.

  • uses (iterable of str, optional) – Text after use for each module-level statement (for example "mykinds, only: dp").

  • **kwargs – See workload_procedures().

The complete module. Its public procedure has the signature of the optional_derivatives=True kernel, so it is a drop-in replacement of that kernel.

workload_procedures(diff: Any, workloads: Sequence[Any], *, derivatives: Any = None, subroutine_name: str | None = None, fixed_nc: Iterable[int] | None = None, extents: Mapping[str, Sequence[str]] | None = None, preset: Preset | str | None = None, options: CodegenOptions | None = None, **kwargs: Any) → str[source]¶

Generate the dispatcher, the fallback and the fixed-output kernels.

Parameters:

  • diff (DiffPlz) – The differentiated expression.

  • workloads (sequence) – One derivative selection per fixed-output kernel, in the format of to_fortran(derivatives=...) (for example "dn,dndn" or ["dT"]). The dispatcher matches the output set of each generated kernel (the function value included when to_fortran emits it), exactly.

  • derivatives (str or list of str, optional) – Derivatives of the fallback kernel and so of the public signature; it must contain every workload. Default: every derivative of diff.

  • subroutine_name (str, optional) – Public name of the dispatcher. The kernels are named <name>_fallback, <name>_w<k> (k from 1, in the order of workloads) and <name>_w<k>_nc<size>. Default: the name of diff.

  • fixed_nc (iterable of int, optional) – Component counts for which every fixed-output kernel is also emitted with nc as a named constant; the dispatcher selects by nc and then by output set.

  • extents (mapping, optional) – Extents of the array inputs by name (for example {"a": ("nc", "ng")}). Inputs without an entry are nc in every dimension, unless the kernel has extra integer dimensions; then they stay assumed shape.

  • preset – Code-generation options as in to_fortran. Other keywords (integer_args, module_symbols, symmetric_params, stats, name) are forwarded to every to_fortran call and every option name is accepted as an override. optional_derivatives is set by this function.

  • options – Code-generation options as in to_fortran. Other keywords (integer_args, module_symbols, symmetric_params, stats, name) are forwarded to every to_fortran call and every option name is accepted as an override. optional_derivatives is set by this function.

  • **kwargs – Code-generation options as in to_fortran. Other keywords (integer_args, module_symbols, symmetric_params, stats, name) are forwarded to every to_fortran call and every option name is accepted as an override. optional_derivatives is set by this function.

Returns:

The subroutines, without a module.

Return type:

str

Raises:

ValueError – If two workloads have the same outputs, a workload is not covered by derivatives or fixed_nc is invalid.
